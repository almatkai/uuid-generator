# Validation record

Source baseline `5a17980eaad254c8e95f845cd8b1002788998695`; branch `feat/native-v2-rust`. All additions are under `v2/`; only a discovery link is appended to the root README. No staging, commit, push, PR, profile/history access or host edits are part of this delivery.

The required gate runner is `python3 scripts/validate.py`. It materializes the standalone nested Cargo test manifests/locks from shipped templates (and restores the local workspace boundary removed by Cargo package normalization), then runs the original execution oracle, pinned schema, formatting, Rust stable and 1.85 tests and strict all-target Clippy, Windows GNU check/Clippy, actual beta renderer checks, disposable original V1 tests/typecheck and immutable input/Git visibility audit. `python3 scripts/package.py` packages, verifies required file inclusion, extracts into `.work/extracted` and runs offline oracle/schema/Rust tests from the actual artifact. Cached Cargo crates (and npm tarballs for disposable V1 typecheck) are required by offline checks; dependency sources are not all bundled. All JS libraries/compiler/validator required by the original oracle and renderer/schema checks are bundled, independent of npm install or the real host.

Validated toolchains: macOS aarch64, Rust stable (1.98.0) and Rust 1.85.0, Node 26.7.0. Windows target: `x86_64-pc-windows-gnu` cross-check; Windows binaries and OS effects are not executed. Locked graphs are retained as Cargo.lock and nested Cargo.lock.template. No tests access the real clipboard, focus, browser or user profile.

Verified test inventory (each Rust toolchain):

- 8 focused engine tests: JS coercion/limits, UUID/TypeID rules, real OS entropy uniqueness, history corruption/unknown-key preservation, monotonic/overflow clocks, formatting and explicit resource errors.
- 3 oracle test functions compare 315 original cases / 342 original command invocations, plus nine direct locked uuid11 state-helper/byte-encoder boundaries. Output text, CRLF, case, history serialization/timestamps, success message and effect selection are compared byte-for-byte. Original toast titles/messages and raw source history serialization before/after deletion are compared; original silent failures become documented explicit errors.
- 21 adapter/lifecycle/effect/persistence/concurrency tests against the real pinned beta common/SDK/NativeSessions, with labelled Tauri/router/registration/installation substitutes. These cover all commands, acknowledged/uncertain effects, cancellation, independent copy/history/hide checkpoints, receipt replay, corruption, 20 concurrent generation sessions, session disposal/uninstall, form drafts, search cloning and action freshness.
- 5 tests from the unchanged beta common/SDK files.
- 7 original V1 tests and original TypeScript typecheck in a disposable copy with npm ci using the unchanged original package-lock.json. Those original tests include a rewritten formatting helper; the additional execution oracle executes the **actual** original formatting command.
- Actual original React history component/actions with recording hooks: nine semantic assertions (load/reversal, Copy All, duplicate deletion, clear confirmation, bad storage). Actual original nine commands include the view-history path, not a subset of generator functions.
- 33 pinned beta renderer parser/reconciliation/action-routing/notice assertions; ListRuntime itself also executes with inert hooks/DOM. The actual parent ExtensionRuntimeView handler also verifies red failure notices; no effect failure is presented as success. This is not visual QA.
- The full unchanged Draft 2020-12 manifest schema validated by vendored Ajv, with 25 negative manifests and exact original command/argument/preference parity.
- Exact icon size/SHA256, immutable fixture/library/license hashes, all V1 source/lock/assets/license bytes and Git visibility (including normally ignored dist directories).

The oracle transpiles byte-exact original TS with the pinned TypeScript compiler, records the Raycast boundary, substitutes deterministic entropy and clock at crypto/Date boundaries, and executes the unchanged locked uuid 11.1.1, nested uuid 10.0.0, ulidx 2.4.1 and typeid-js 1.2.0 distributions. Both UUIDv7 implementations and ULID repeated/backwards clock/randomness behavior are checked. All five generators execute count 10000 through their real source; count 10001, negative/zero/default/Unicode whitespace/numeric/array inputs and validation precedence are covered. TypeID sequence wrap is seeded through the actual library's options, and uuid11 wrap uses its actual exported helper and byte encoder. Production uses OS entropy/clock and process-wide monotonic state, without deterministic product output.

Host integration/rebuild/catalog registration and real macOS/Windows UI, clipboard, focus and paste QA remain **not-run**. No visual QA is inferred from headless parsing. Exact Raycast HUD/toast, shortcuts and metadata/tooltips are limited by the beta renderer; see README and INTEGRATION. XERJ was unreachable: its coverage is incomplete, no global restart was attempted, and source inspection used rg/direct reads.

The optional `scripts/validate.py --recorded-oracle` reruns all remaining gates while reusing hash-verified oracle data; both Rust toolchains still compare every oracle case. The default and extracted-package validation execute the original Node oracle again.
